# Виджеты Sonora

Sonora ставит на домашний экран несколько независимых виджетов. В списке выбора
сейчас пять записей: четыре фиксированных (2×2, 4×1, 4×2, 4×4) и старый
универсальный «авто»-виджет. Все сделаны на классическом `RemoteViews` (без
Glance и Compose), потому что виджет живёт в чужом процессе лаунчера.

## Виджеты в списке выбора

В списке выбора все пять записей показываются под именем приложения «Sonora»,
различаются подписью (`android:description`):

| Подпись в пикере | Размер | Файл раскладки | Что показывает |
| --- | --- | --- | --- |
| Компактный плеер 2×2 | 2×2, без ресайза | `widget_sonora_small.xml` | обложка во всю высоту, название в 2 строки, исполнитель, прогресс, play/pause поверх обложки; prev/next нет |
| Плеер 4×1 | 4×1, без ресайза | `widget_sonora.xml` | обложка 56dp, название, исполнитель, прогресс, кнопки prev/play/next по 40dp |
| Плеер 4×2 с обложкой | 4×2, без ресайза | `widget_sonora_large.xml` | обложка 92dp слева, название 16sp, исполнитель 13sp, прогресс, кнопки прижаты к низу |
| Большой плеер 4×4 | 4×4, без ресайза | `widget_sonora_xlarge.xml` | обложка сверху на всю ширину, название 18sp в 2 строки, исполнитель 14sp, прогресс, ряд кнопок 48dp |
| Текущий трек и управление воспроизведением (старый «авто») | любой, ресайзится | по фактическому размеру | сам выбирает 2×2 / 4×1 / 4×2–4×4 под размер экземпляра |

### Старый «авто»-виджет

`SonoraWidgetProvider` остался в манифесте, чтобы уже размещённые виджеты не
пропали после обновления приложения. Он, как и раньше, подбирает раскладку по
`AppWidgetManager.getAppWidgetOptions`: ширина < 190dp или почти квадрат — 2×2;
высота ≥ 110dp — большая; иначе широкая. Этот же провайдер удобно использовать,
если нужен один виджет, который сам подстраивается под изменение размера.

## Как добавить

1. Долгое нажатие на свободном месте экрана → «Виджеты».
2. Найдите Sonora и выберите нужный размер из списка выше.
3. Перетащите на экран. Фиксированные виджеты не ресайзятся
   (`resizeMode="none"`), «авто» — ресайзится.

## Как выбирается раскладка

В `SonoraWidget` есть список `PROVIDER_SPECS`: для каждого зарегистрированного
провайдера указано, фиксированная у него раскладка или автоматическая. При
каждом обновлении `updateAll` собирает id всех экземпляров всех провайдеров,
для каждого читает options и строит `RemoteViews` по правилу провайдера. Список
в коде обязан совпадать с `<receiver>` в `AndroidManifest.xml`.

## Обложка и кэширование

* Берётся `Track.artworkUrl`, иначе `Track.artworkUri`. Пока картинки нет —
  иконка-нота на скруглённой подложке.
* Грузится через Coil в фоне (`size(300)`, `allowHardware(false)`), углы
  скругляются вручную (`Canvas` + `Path`), потому что `RemoteViews` не умеет
  `clipToOutline`.
* Битмап кэшируется в памяти по id трека (`ConcurrentHashMap`, максимум
  несколько штук): прогресс приходит ~раз в секунду, повторно картинку не
  качаем.
* Неудачные загрузки запоминаются, чтобы не дёргать сеть на каждом апдейте.
* URL последней обложки сохраняется в `SharedPreferences` (`last_artwork`),
  поэтому после смерти процесса виджет сначала показывает последний трек, а
  обложку догружает из дискового кэша Coil.

## Обновления

Виджеты не опрашивают состояние сами: `android:updatePeriodMillis="0"` —
система их не будит. Всё «толкается» из процесса приложения:

* `PlaybackController` вызывает `SonoraWidget.updateAll(context, state)` при
  изменении `PlayerUiState`, но не чаще раза в секунду;
* `BaseSonoraWidgetProvider.onUpdate` — когда виджет добавлен на экран;
* `onAppWidgetOptionsChanged` — когда у «авто»-виджета изменился размер;
* после нажатия кнопки ресивер сам перерисовывает виджеты.

`updateAll(context)` читает `AppGraph.playback.state.value` и нужен там, где
готового состояния под рукой нет (onUpdate, ресайз).

## Кнопки

Каждая кнопка — `PendingIntent.getBroadcast` на явный (`setComponent`) intent
с action `app.sonora.widget.PLAY_PAUSE`, `.NEXT`, `.PREVIOUS` и флагами
`FLAG_IMMUTABLE | FLAG_UPDATE_CURRENT`. Все провайдеры наследуются от
`BaseSonoraWidgetProvider`, который ловит действие, вызывает
`togglePlayPause()` / `next()` / `previous()` у `AppGraph.playback` и
обновляет виджеты. Тап по карточке открывает `MainActivity`.

## Холодный процесс

Если процесс приложения убит, первое нажатие кнопки его стартует, а
`MediaController` подключается асинхронно — команду может понадобиться
повторить. До первого обновления виджеты показывают последний сохранённый трек
из `SharedPreferences`, а если трека ещё не было — заглушку «Sonora».

## Ограничения

* `RemoteViews` не поддерживает анимации, скролл, кастомные View и
  `clipToOutline`; обложка передаётся как готовый битмап, прогресс не
  анимируется.
* В 4×4-раскладке обложка занимает всю свободную высоту сверху и кропится
  `centerCrop`: точные пропорции квадрата RemoteViews не гарантирует.
* Превью в списке виджетов (`previewLayout`) работает на Android 12+; на более
  старых версиях показывается иконка приложения.
* Раскладки фиксированных виджетов не меняются при изменении размера — для
  этого есть «авто»-виджет.

## Файлы

* `widget/SonoraWidget.kt` — обновление, выбор раскладки, обложка, кэш.
* `widget/BaseSonoraWidgetProvider.kt` — общая логика всех провайдеров.
* `widget/SonoraWidgetProvider.kt` — legacy «авто».
* `widget/SonoraWidget2x2Provider.kt`, `...4x1Provider.kt`, `...4x2Provider.kt`,
  `...4x4Provider.kt` — фиксированные виджеты.
* `res/layout/widget_sonora*.xml` — раскладки.
* `res/xml/sonora_widget_info.xml`, `sonora_widget_2x2.xml`,
  `sonora_widget_4x1.xml`, `sonora_widget_4x2.xml`, `sonora_widget_4x4.xml` — метаданные.
