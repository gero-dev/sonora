# Поиск песни по аудиофрагменту

> Статус: **2.3.0**. На экране поиска есть кнопка «Найти по фрагменту»:
> приложение записывает 8 секунд звука, распознаёт песню и **в фоне** ищет
> информацию по названию и исполнителю. Воспроизведение при этом не
> прерывается, интерфейс не блокируется.

## Как это работает

1. **Запись** — `AudioRecord`, 16 кГц, моно, PCM 16 бит, 8 секунд, на
   `Dispatchers.IO`; главный поток свободен. Разрешение `RECORD_AUDIO`
   запрашивается через системный диалог.
2. **Распознавание**:
   - если в настройках панели указан ключ **AudD** — multipart-запрос
     `https://api.audd.io/` возвращает title/artist/album/artwork;
   - если ключа нет — **офлайн-fallback**: упрощённый спектральный отпечаток
     фрагмента сверяется с отпечатками локальной фонотеки (лениво, до 200
     треков, кэш в `filesDir`). Это узнаёт только песни, которые уже есть
     на устройстве.
3. **Обогащение в фоне** — найденные название/исполнитель прогоняются через
   существующие `AppGraph.metadata` и `AppGraph.youtube`; UI показывает
   «Ищем информацию…», затем кандидатов. Клик по кандидату заполняет обычный
   поиск (воспроизведение не запускается само).
4. **Состояние** живёт в процессе приложения: уход с экрана не отменяет
   поиск; свайп приложения — отменяет (foreground-сервиса нет).

## Что выбрать: AudD или локальный fallback

| | AudD | Локальный отпечаток |
|---|---|---|
| Что узнаёт | любую песню из базы AudD | только файлы своей фонотеки |
| Ключ | бесплатные 300 запросов после регистрации | не нужен |
| Точность | высокая | эвристика, возможны ложные срабатывания |
| Приватность | фрагмент уходит на api.audd.io | всё на устройстве |

Ключ вводится в панели распознавания и хранится в отдельных prefs модуля
(`sonora_recognition`), не в общих настройках. Без ключа приложение честно
пишет, что распознавание идёт по локальной фонотеке.

## Исследование бесплатных API (октябрь 2026)

| Сервис | Условия | Итог |
|---|---|---|
| [AudD](https://docs.audd.io/) | 300 бесплатных запросов, потом платно | выбран: простой multipart API, работает с Android |
| [ShazamKit](https://developer.apple.com/shazamkit/) | нужен Apple Developer Program и подписанный токен | не free/no-key |
| Shazam unofficial | сигнатура вытаскивается из APK, ломается, нарушает ToS | не используем |
| [AcoustID](https://acoustid.org/webservice) + Chromaprint | бесплатно, но нужен client key и нативный fingerprint (NDK) | избыточно для этой задачи |
| [ACRCloud](https://www.acrcloud.com/pricing/) | trial, дальше metered | не free |

Надёжного **keyless** API распознавания в 2026 нет, поэтому выбран AudD
(ключ опционален) + честный офлайн-fallback.

## Ограничения

- Локальный fallback — эвристика: на синтетических тестах та же запись с шумом
  даёт сходство 0.74–1.0, разные песни — 0.4–0.55, порог 0.62. Возможны
  ложные срабатывания; это не замена AudD.
- Первый проход локального индекса может занять минуты (декодирование до
  200 файлов через MediaExtractor/MediaCodec). Процесс в фоне, отменяемый.
- Запись с микрофона требует тишины/слышимости; при ошибке микрофона
  показывается понятное сообщение.
- Нет обработки после смерти процесса (осознанно: без foreground-сервиса).
