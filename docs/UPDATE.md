# Обновления из GitHub

> Статус: **1.9.0**. Sonora умеет сама узнавать о новых версиях и — только по
> желанию пользователя — скачать и установить APK из GitHub Releases.

## 1. Как это работает

1. **Автопроверка** запускается через несколько секунд после старта и дальше
   раз в сутки (фоновый цикл). Если пользователь выключил «Проверять обновления
   автоматически», проверка выполняется только по кнопке.
2. Запрос идёт на `https://api.github.com/repos/gero-dev/sonora/releases/latest`.
   Если GitHub API ответил 403/429 (лимит 60 запросов/час на IP), используется
   резервный путь: `https://github.com/gero-dev/sonora/releases/latest` с
   редиректом на тег и предсказуемым именем файла
   `Sonora-<версия>-debug.apk`.
3. Результат кэшируется в `filesDir/update_cache.json` (версия, ссылка, размер,
   SHA-256, ETag, время проверки). Повторная сеть — не чаще суток; после ошибки
   — не чаще часа.
4. Версия сравнивается с установленной `BuildConfig.VERSION_NAME` посегментно
   (`1.10.0 > 1.9.0`).

## 2. Что видит пользователь

«Настройки → Обновления»:

- текущая версия;
- переключатель «Проверять обновления автоматически»;
- «Проверить обновления» — статус: проверяем / доступна X / последняя версия /
  ошибка;
- карточка новой версии: номер, размер, «Что нового» (из тела релиза);
- **«Скачать и установить»** — скачивание APK с прогрессом и возможностью
  отменить; после скачивания открывается системный установщик;
- «Позже» — отложить именно эту версию (авто-напоминания о ней прекращаются);
- «Открыть релизы на GitHub» — страница релизов в браузере.

Если Android запрещает установку из неизвестных источников, кнопка меняется на
«Разрешить установку» и открывает системную настройку для Sonora.

## 3. Безопасность и приватность

- **Ничего не устанавливается само**: скачивание и установка — только по
  нажатию, с системным подтверждением установщика.
- Скачанный APK проверяется по **SHA-256** из `digest` релиза GitHub (если поле
  есть), затем сверяется минимальный размер.
- Ссылки на скачивание — только с домена `github.com` из наших релизов; APK
  подписан тем же debug-ключом, поэтому обновление поверх установленной версии
  проходит штатно.
- Приватность: на GitHub уходит только стандартный запрос версии (без id
  устройства и аккаунта).

## 4. Ограничения

- **Debug-подпись**: релизные APK подписаны debug-ключом. Обновление сработает,
  только если установленная копия подписана тем же ключом (обычный случай для
  установки из Releases). Сборка из другого keystore потребует переустановки.
- GitHub API без токена ограничен 60 запросами в час на IP; поэтому кэш на
  сутки и резервный путь без API.
- Если GitHub недоступен без обхода, проверка обновлений не работает (как и
  скачивание); приложение просто покажет «не удалось проверить».

## 5. Где это в коде

| Компонент | Файл |
|---|---|
| Проверка, кэш, скачивание, SHA-256, установка | `data/update/UpdateManager.kt` |
| Модели и сравнение версий | `data/update/UpdateModels.kt` |
| UI «Настройки → Обновления» | `ui/screens/SettingsScreen.kt` |
| Автопроверка при старте | `ui/MainViewModel.kt` (init) |
| FileProvider и разрешение | `AndroidManifest.xml`, `res/xml/update_file_paths.xml` |
