# NoHiT: DPI-обход в Sonora вместо WARP

> Статус: **2.0.0**. Встроен [NoHiT](https://github.com/Avedanger/NoHiT)
> (Apache-2.0): DoH/GeoHide DNS + фрагментация TLS ClientHello + автоподбор
> стратегии. Исходники лежат в `app/src/main/java/dev/nohit/core/` (вендоринг,
> чтобы не тянуть отдельный Gradle-модуль под AGP 9), лицензия —
> `app/src/main/assets/licenses/NoHiT-APACHE-2.0.txt`.

## Что именно интегрировано

| Компонент NoHiT | Куда встроен |
|---|---|
| `NoHiT.init` / конфиг | `AppGraph` (при старте), настройки Sonora |
| `NohitDns` (DoH Cloudflare/Google/AdGuard + UDP GeoHide) | резолвинг в локальном прокси и AutoTuner |
| `SplitPlan` (S1–S5: куски ClientHello по 1–8 байт) | локальный прокси `app.sonora.net.nohit.NohitProxy` |
| `AutoTuner` | кнопка «Стратегия NoHiT» в «Настройки → Поток и сеть», автораз в неделю в фоне |
| `NoHiT.client()` | используется через общий `Http.client` (OkHttp) |

## Зачем локальный прокси, а не только `NoHiT.client()`

`NoHiT.client()` — это `Dns` + `SocketFactory` для одного `OkHttpClient`. Он не
покрывает:

- **Ktor** (движок InnerTubeX) — у него свой OkHttp-клиент;
- **Python-рантайм yt-dlp** — фрагментацию на уровне сокета Java в другой процесс
  не передать;
- **ExoPlayer** — пока не подключён `OkHttpDataSource`, он ходит мимо OkHttp.

Поэтому Sonora поднимает локальный HTTP CONNECT-прокси на `127.0.0.1` и
направляет через него сразу все четыре канала:

- `Http.client` (поиск, метаданные, InnerTube API, зеркала, загрузки);
- Ktor OkHttp-движок InnerTubeX (`proxy(...)` в `config`);
- ExoPlayer — через `OkHttpDataSource` с общим клиентом;
- yt-dlp — автоматически добавляется `--proxy http://127.0.0.1:<port>`, если
  пользователь не задал свой прокси.

Прокси резолвит апстрим через `NohitDns` и режет первые байты каждого
CONNECT-туннеля по плану `SplitPlan` (используется `FragOutputStream` из NoHiT).
Слушает только loopback, наружу не открыт.

## Настройки

«Настройки → Поток и сеть → DPI-обход (NoHiT)»:

- переключатель «Обход блокировок NoHiT» (по умолчанию включён);
- «Стратегия NoHiT» — текущая DNS/фрагментация и кнопка автоподбора;
- WARP остался ниже как **резерв**: «WARP-автопилот» по умолчанию включён и
  поднимает туннель, только если NoHiT не дал результата.

## Результаты проверки на реальной сети РФ (29.10.2026)

Проверялось на сети пользователя (МТС/домашний Wi-Fi, TSPU) с полностью
выключенным WARP на ПК:

| Проверка | Результат |
|---|---|
| Прокси NoHiT запускается | ✅ `DPI-прокси запущен на 127.0.0.1:…` |
| AutoTuner | ✅ `ok=true`, DNS GeoHide, split `[2,2,2,2]`, 542 мс (для незаблокированных хостов) |
| TLS до `music.youtube.com` через фрагментацию | ❌ по-прежнему обрыв (TSPU собирает TCP-поток и читает SNI из пересобранных данных) |
| yt-dlp через `--proxy` NoHiT | ❌ `SSL: UNEXPECTED_EOF_WHILE_READING` |
| Прямой InnerTube через NoHiT | ❌ `api reachable=false` |

Вывод: **NoHiT полностью интегрирован и работает как задумано, но на этой сети
его сегментация ClientHello не обходит блокировку.** Это соответствует
разделу «Честные ограничения» самого NoHiT: против TSPU с reassembly нужен
внешний транспорт. Поэтому WARP не удалён, а оставлен автоматическим резервом:
Sonora сначала использует NoHiT (и его DNS), а если YouTube недоступен —
поднимает WARP и играет через yt-dlp. Пользователю по-прежнему ничего не нужно
включать вручную.

Если провайдер не собирает TCP (или блокирует только DNS), NoHiT справляется
сам и WARP не запускается — это проверяется автопилотом на каждой сети.

## Ограничения и приватность

- NoHiT не создаёт VPN, не меняет системную сеть и не скрывает IP.
- GeoHide DNS видит DNS-запросы; можно выбрать DoH-провайдера в конфигурации
  NoHiT (автоподбор учитывает порядок).
- Фрагментация не помогает против блокировки по IP, JA3/JA4, ECH, полных
  шатдаунов и троттлинга CDN — см. `docs/LIMITS.md` в репозитории NoHiT.
- Лицензия NoHiT — Apache-2.0; копия в APK и `THIRD-PARTY-NOTICES.md`.
