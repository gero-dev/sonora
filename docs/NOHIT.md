# NoHiT: DPI-обход в Sonora вместо WARP

> Статус: **3.0.0**. NoHiT — единственный DPI-обход, обновлён до **0.3.0-alpha.5** (`nohit-core` вендорен из тега).
>. Встроен [NoHiT](https://github.com/Avedanger/NoHiT)
> (Apache-2.0): DoH/GeoHide DNS + фрагментация TLS ClientHello + автоподбор
> стратегии. Исходники лежат в `app/src/main/java/dev/nohit/core/` (вендоринг,
> чтобы не тянуть отдельный Gradle-модуль под AGP 9), лицензия —
> `app/src/main/assets/licenses/NoHiT-APACHE-2.0.txt`.

## Что именно интегрировано

| Компонент NoHiT | Куда встроен |
|---|---|
| `NoHiT.init` / конфиг | `AppGraph` (при старте), настройки Sonora |
| `NohitDns` (DoH Cloudflare/Google/AdGuard + UDP GeoHide) | резолвинг в локальном прокси и AutoTuner |
| `SplitPlan` (S1–S5: куски ClientHello по 1–8 байт) | локальный прокси `app.sonora.net.nohit.NohitProxy` |
| `AutoTuner` | кнопка «Стратегия NoHiT» в «Настройки → Поток и сеть», автораз в неделю в фоне |
| `TlsFraming` / `SplitPlan.TLS_*` / `SNI_*` (0.3) | законная переупаковка TLS-записи ClientHello и разрез по SNI — новые стратегии автоподбора |
| `HostPolicy` / `skipHosts` (0.3) | банки/госуслуги не фрагментируются: прокси уважает policy |
| `NetworkChangeWatcher` / `GeoHideUpdater` (0.3) | сброс DNS-кэша при смене сети и обновление списка GeoHide в фоне |
| `NoHiT.client()` | используется через общий `Http.client` (OkHttp) |

## Зачем локальный прокси, а не только `NoHiT.client()`

`NoHiT.client()` — это `Dns` + `SocketFactory` для одного `OkHttpClient`. Он не
покрывает:

- **Ktor** (движок InnerTubeX) — у него свой OkHttp-клиент;
- **Python-рантайм yt-dlp** — фрагментацию на уровне сокета Java в другой процесс
  не передать;
- **ExoPlayer** — пока не подключён `OkHttpDataSource`, он ходит мимо OkHttp.

Поэтому Sonora поднимает локальный HTTP CONNECT-прокси на `127.0.0.1` и
направляет через него сразу все четыре канала:

- `Http.client` (поиск, метаданные, InnerTube API, зеркала, загрузки);
- Ktor OkHttp-движок InnerTubeX (`proxy(...)` в `config`);
- ExoPlayer — через `OkHttpDataSource` с общим клиентом;
- yt-dlp — автоматически добавляется `--proxy http://127.0.0.1:<port>`, если
  пользователь не задал свой прокси.

Прокси резолвит апстрим через `NohitDns` и режет первые байты каждого
CONNECT-туннеля по плану `SplitPlan` (используется `FragOutputStream` из NoHiT).
Слушает только loopback, наружу не открыт.

## Настройки

«Настройки → Поток и сеть → DPI-обход (NoHiT)»:

- переключатель «Обход блокировок NoHiT» (по умолчанию включён);
- «Стратегия NoHiT» — текущая DNS/фрагментация и кнопка автоподбора;
- WARP остался ниже как **резерв**: «WARP-автопилот» по умолчанию включён и
  поднимает туннель, только если NoHiT не дал результата.

## Обновление до 0.3.0-alpha.2

- Вендорены 13 файлов `nohit-core` из тега `v0.3.0-alpha.5` (было 5 из 0.1.1): добавлен `AddressClassifier` (фильтр приватных адресов в DNS-ответах, включён по умолчанию), улучшены резолвер и автообновление GeoHide.
- Автоподбор теперь умеет TLS-record фрагментацию (`TLS_64/128/256`, комбинации с TCP и SNI-разрезом) — это законно по RFC 8446 §5.1; старые `chunks`-пресеты `S1–S5` удалены, сохранённые конфиги читаются обратно.
- Прокси Sonora применяет `HostPolicy` из конфига: `skipHosts` (банки, госуслуги) идут без вмешательства в TLS.
- `NoHiT.init()` сам ставит `NetworkChangeWatcher` (сброс DNS-кэша при смене сети) и `GeoHideUpdater` (обновление списка GeoHide).

## Результаты проверки на реальной сети РФ (29.10.2026)

Проверялось на сети пользователя (МТС/домашний Wi-Fi, TSPU) с полностью
выключенным WARP на ПК:

| Проверка | Результат |
|---|---|
| Прокси NoHiT запускается | ✅ `DPI-прокси запущен на 127.0.0.1:…` |
| AutoTuner | ✅ `ok=true`, DNS GeoHide, split `[2,2,2,2]`, 542 мс (для незаблокированных хостов) |
| TLS до `music.youtube.com` через фрагментацию | ❌ по-прежнему обрыв (TSPU собирает TCP-поток и читает SNI из пересобранных данных) |
| yt-dlp через `--proxy` NoHiT | ❌ `SSL: UNEXPECTED_EOF_WHILE_READING` |
| Прямой InnerTube через NoHiT | ❌ `api reachable=false` |

Вывод: **NoHiT полностью интегрирован и работает как задумано, но на этой сети
его сегментация ClientHello не обходит блокировку.** Это соответствует
разделу «Честные ограничения» самого NoHiT: против TSPU с reassembly нужен
внешний транспорт.

Ранее здесь было написано, что «WARP не удалён и оставлен автоматическим
резервом». **Это уже неверно.** WARP (userspace wireguard-go) был удалён из
проекта в Sonora 3.0.0, и сейчас резерва нет: в репозитории не осталось ни
`VpnService`, ни `BIND_VPN_SERVICE` в манифесте, ни `.so`-библиотек туннеля.
Автопилот (`StreamingAutoPilot`) проверяет два пути — прямой и yt-dlp через
локальный прокси NoHiT, — и оба упираются в тот же обрыв TLS на сети с TSPU.

Практический итог для пользователя в сети с TSPU: **онлайн-воспроизведение
через YouTube не работает, и автоматического обхода в приложении нет.**
Локальные файлы и уже сохранённые треки играются нормально. Подробнее о том,
почему так и что потребовалось бы для настоящего обхода, — в разделе
«VLESS + Reality» ниже.

Если провайдер не собирает TCP (или блокирует только DNS), NoHiT справляется
сам — это проверяется автопилотом на каждой сети.

## VLESS + Reality / XTLS-Vision: почему этого нет

Запрос «заставить NoHiT обходить ТСПУ через VLESS + Reality» **в текущей
архитектуре невыполним**, и это не вопрос трудозатрат.

NoHiT — это ~3000 строк чистого Kotlin **без криптографии и без туннеля**. Он
делает ровно одно: переразбивает TLS ClientHello так, чтобы SNI не попал в
один TCP-сегмент, и подменяет DNS на DoH. Против ТСПУ, который пересобирает
TCP-поток и читает SNI уже из пересобранных данных, это структурно
недостаточно — что и подтвердили измерения выше.

VLESS + Reality — это другой класс решения: настоящий шифрованный туннель,
которому нужны:

- X25519-рукопожатие и подмена TLS-отпечатка (Reality);
- TLS-in-TLS с мультиплексированием (XTLS-Vision);
- TUN-интерфейс (`VpnService`) и userspace-стек для маршрутизации пакетов.

Реализовать это на Kotlin вручную — значит написать криптографический стек,
ошибка в котором ломает не скорость, а приватность. Реалистичный путь —
подключить готовое ядро (Xray-core, MPL-2.0, или sing-box, GPL-3.0) как
`.so` под каждый ABI плюс `VpnService` с tun2socks. Лицензия не мешает:
Sonora уже распространяется под GPL-3.0.

Цена: **+15–25 МБ на каждую ABI** (то есть +60–90 МБ к APK), 4 новых ABI-сборки,
`VpnService` с постоянным уведомлением и ~6–10 новых файлов. Это отдельная
крупная задача, а не правка существующего обхода, поэтому в эту версию она не
вошла.


## Ограничения и приватность

- NoHiT не создаёт VPN, не меняет системную сеть и не скрывает IP.
- GeoHide DNS видит DNS-запросы; можно выбрать DoH-провайдера в конфигурации
  NoHiT (автоподбор учитывает порядок).
- Фрагментация не помогает против блокировки по IP, JA3/JA4, ECH, полных
  шатдаунов и троттлинга CDN — см. `docs/LIMITS.md` в репозитории NoHiT.
- Лицензия NoHiT — Apache-2.0; копия в APK и `THIRD-PARTY-NOTICES.md`.
