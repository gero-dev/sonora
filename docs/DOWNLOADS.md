# Сохранение треков

Sonora умеет сохранять **любой трек, который уже умеет играть**: из InnerTube
(YouTube Music), из открытых каталогов, по прямой HTTPS-ссылке и из Spotify-превью.
Файл попадает в приватную папку приложения, после чего трек становится обычным
локальным треком библиотеки.

> Документ описывает пользовательский сценарий и внутреннее устройство. Краткая
> инструкция также встроена в приложение: **Настройки → Импорт из других платформ →
> Как это работает** и в карточке загрузки.

---

## 1. Что можно сохранить

| Источник | Что сохраняется | Ограничения |
|---|---|---|
| **InnerTube / YouTube Music** | MP4-аудиопоток (обычно itag 140 / AAC) | Нужна сеть; скачивание с YouTube может нарушать ToS |
| **Internet Archive** | Оригинальный файл (MP3/FLAC/OGG) | Только треки с открытой лицензией |
| **Jamendo** | Оригинальный файл | Только `audiodownload_allowed = true` |
| **Прямой HTTPS-поток** | Ответ сервера как файл | Сервер должен отдавать сам аудиофайл, а не страницу/HLS-плейлист |
| **Spotify** | Только 30-секундное превью, если оно есть | Полные треки защищены DRM и не сохраняются |
| **SoundCloud** | Ничего | API/ToU запрещают офлайн-копирование; треки не играются внутри Sonora |
| **Локальный файл** | Уже находится на устройстве | Кнопка скрыта, повторное копирование не нужно |

Важно: Sonora **не обходит DRM** и не собирает HLS/DASH-сегменты в один файл.
Если ссылка ведёт на плейлист `.m3u8`, будет сохранён только текст плейлиста,
а не музыка. Для DRM-контента (полный Spotify, SoundCloud Go+) сохранение
недоступно.

## 2. Как сохранить трек

### Из плеера

1. Запустите трек.
2. Нажмите иконку **стрелки вниз** в ряду действий под обложкой.
3. Дождитесь замены иконки на **галочку** — файл сохранён.

Во время загрузки на месте иконки показывается круговой индикатор. При ошибке
иконка становится красной: нажмите её ещё раз, чтобы повторить.

### Из списка треков

1. Долго нажмите на трек в **Медиатеке**, **Поиске**, **Главной** или на экране
   плейлиста/альбома.
2. Выберите **«Скачать»**.
3. Если трек уже сохранён, пункт не показывается; в плеере вместо кнопки будет
   галочка «Уже скачано».

### Из открытых каталогов

В разделе **Обзор** у треков Internet Archive и Jamendo есть отдельная кнопка
скачивания. Она сохраняет оригинальный файл и добавляет его в библиотеку.

## 3. Что происходит после сохранения

1. Файл копируется в приватную папку приложения:
   `Android/data/app.sonora/files/Music/Sonora/` (если внешнее хранилище
   недоступно — во внутреннюю `filesDir`).
2. Имя формируется как **«Исполнитель - Название.расширение»**; одинаковые имена
   не перезаписываются — добавляется суффикс.
3. Обложка скачивается в `filesDir/covers` и привязывается к локальному треку.
4. Для YouTube-трека подтягиваются альбом, текст (LRCLIB/InnerTube) и метаданные,
   если их не было.
5. Локальная копия получает в `extra`:
   - `youtubeId` — идентификатор ролика (для InnerTube);
   - `downloadedTrackId` — id исходного онлайн-трека;
   - `downloadedFrom` — исходный источник;
   - `downloadedAt` — время сохранения.
6. Библиотека пересканируется, и трек появляется во вкладках **Треки**,
   **Альбомы**, **Исполнители**, **Плейлисты** и **Избранное** (если добавлен).

Повторное нажатие «Скачать» для того же трека блокируется: Sonora ищет локальную
копию по `downloadedTrackId` или `youtubeId`.

---

## 4. Где лежат файлы

| Что | Путь |
|---|---|
| Аудио | `Android/data/app.sonora/files/Music/Sonora/` |
| Обложки | `Android/data/app.sonora/files/covers/` |
| Метаданные библиотеки | `filesDir/library.json` и соседние JSON-файлы |

Путь `Android/data` может быть скрыт в системном проводнике Android 11+.
Открыть его можно через «Проводник» с доступом к Android/data, через файловый
менеджер с root или через подключение к компьютеру. Внутри приложения трек
всегда доступен в Медиатеке.

Удаление файла вне приложения не удаляет запись сразу: нажмите
**«Пересканировать»** в Медиатеке. Удаление приложения удаляет и приватную папку.

## 5. Настройки и состояния

- **Только Wi-Fi** (`downloadWifiOnly`): при сотовой сети загрузка не начнётся,
  появится ошибка «Только Wi-Fi». Отключите ограничение в настройках, если нужен
  мобильный интернет.
- **Прогресс**: `DownloadManager` публикует `StateFlow` с процентом; список
  загрузок и плеер показывают состояние.
- **Статусы**: «Скачивание», «Готово», «Уже скачано», «Ошибка: <причина>»,
  «Недоступно», «Уже на устройстве».
- **Отмена**: прервите загрузку повторным нажатием в списке загрузок или
  закройте приложение; недокачанный файл имеет расширение `.part` и не попадает
  в библиотеку.

## 6. Если что-то пошло не так

| Симптом | Что проверить |
|---|---|
| «Только Wi-Fi» | Отключите «Скачивать только по Wi-Fi» или подключитесь к Wi-Fi |
| «Ошибка: 403/410» | Поток устарел; Sonora уже пробует резервный поток. Если не помогло — обновите трек в поиске и повторите |
| «Ошибка: 429» | Слишком много запросов к InnerTube; подождите несколько минут |
| «Ошибка: Range не принят сервером» | Сервер не поддерживает куски; приложение переключится на обычный поток, повторите |
| Загрузка зависла на 0 % | Проверьте VPN/WARP, доступ к `googlevideo.com`; попробуйте другую сеть |
| Файл сохранился, но не играет | Формат мог быть сохранён неверно (например, HLS); удалите трек и скачайте заново |
| Нет обложки | Обложка недоступна у источника; нажмите «Обогатить метаданные» в настройках |
| Трек не появился в альбомах | У трека нет альбома у источника; заполните теги вручную или обогатите метаданные |
| «Недоступно» | Источник не отдаёт файл (Spotify без превью, SoundCloud, DRM) |

Технические причины смотрите в `logcat` по тегам `DownloadManager` и
`InnerTubeStreams`.

---

## 7. Правовая рамка

- Сохранение **своих** файлов и музыки с лицензиями CC/PD — разрешено.
- Сохранение из открытых каталогов — только при наличии соответствующей лицензии;
  Sonora показывает её в карточке трека.
- Сохранение из InnerTube/YouTube — для **личного офлайн-доступа**. Это может
  нарушать условия YouTube; файлы не распространяются и остаются на устройстве.
- Spotify-превью — только тот фрагмент, который официально отдал сервис.
- Sonora не предоставляет публичный доступ к сохранённым файлам и не обходит DRM.

Подробнее — [LEGAL.md](LEGAL.md) и [PLATFORM-FACTS.md](PLATFORM-FACTS.md).

## 8. Как это устроено в коде

### 8.1. Почему раньше появлялось «не удалось скачать»

InnerTubeX с включённым `allowBoundedRange` может отдать ссылку, которая
принимает только куски (`Range: bytes=…`). Старый код делал один полный GET,
получал 403/416 и показывал общую ошибку. Теперь:

1. `StreamInfo` несёт `contentLength`, `requireBoundedRange`, `rangeChunkSizeBytes`
   и `useRangeChunks`.
2. `DownloadManager` скачивает bounded-range поток последовательными Range-чанками
   (по умолчанию 1 МБ) и собирает файл.
3. Если ссылка всё равно отклонена (403/410/416) или сервер не принял Range,
   `MainViewModel.downloadInnerTubeFile()` сбрасывает кэш ссылки и пробует
   резервный `player`-поток InnerTube, затем свежий MP4-поток InnerTubeX.
4. В запрос всегда добавляются `User-Agent`, `Accept` и `Accept-Encoding: identity`;
   без них `googlevideo` тоже может ответить 403.
5. Ошибка в UI теперь содержит настоящую причину (`HTTP 403`, `Только Wi-Fi`,
   `Range не принят сервером`), а не безликое «не удалось скачать».

### 8.2. Поток данных

```
UI (PlayerScreen / TrackActionSheet)
  → MainViewModel.downloadTrack(track)
      ├─ Source.YOUTUBE или uri = innertube:<id>
      │    → downloadYouTube(track)
      │       → downloadInnerTubeFile(videoId)
      │         ├─ InnerTubeX MP4 (bounded range)
      │         ├─ fallback player-поток InnerTube
      │         └─ повторный InnerTubeX после invalidate
      │       → DownloadManager.download(
      │            headers, contentLength, rangeChunkSize, requireBoundedRange)
      │       → DownloadManager.downloadArtwork(...)
      │       → MetadataService.lookup + InnerTube lyrics
      │       → Track(source=LOCAL, extra[youtubeId, downloadedTrackId,
      │             artistImageUrl, artistImageUri, artistBio, genre])
      │
      ├─ прямой HTTPS-поток
      │    → DownloadManager.download(url, fileName, mime)
      │    → MetadataService.lookup + обложка/фото автора
      │    → Track(source=LOCAL, extra[downloadedFrom, downloadedTrackId])
      │
      └─ локальный трек → «Уже на устройстве»

LibraryRepository.upsertLocalTracks() + scanLocal()
  → локальная копия видна во всех вкладках
```

Ключевые файлы:

- `ui/MainViewModel.kt` — маршрутизация `downloadTrack`/`downloadYouTube`,
  повторные попытки, статусы `trackDownloads`/`youtubeDownloads`;
- `data/download/DownloadManager.kt` — HTTP-загрузка, Range-чанки, имена, `.part`,
  Wi-Fi-only, заголовки;
- `data/remote/youtube/innertube/InnerTubeStreams.kt` — кэш потоков, fallback,
  корректный `invalidate` по `videoId|quality`;
- `data/remote/youtube/innertube/InnerTubeXEngine.kt` — InnerTubeX, PoToken и
  range-флаги;
- `data/library/LibraryRepository.kt` — `upsertLocalTracks`, `mergeScanned`,
  фото автора, группировка;
- `ui/components/TrackRow.kt` — лист действий и кнопка скачивания;
- `ui/screens/PlayerScreen.kt` — кнопка и состояния в плеере.
