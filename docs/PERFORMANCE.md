# Производительность интерфейса

> Статус: **2.1.0**. Собраны изменения, которые убрали подтормаживания и
> залипания UI. Замеры — на эмуляторе Pixel, debug-сборка, один и тот же
> сценарий прокрутки Главной и Медиатеки.

## 1. Что было главной причиной

Плеер обновлял `PlayerUiState` каждые 500 мс (позиция трека), а экраны
подписывались на **весь** `vm.player`. Из-за этого Главная, Медиатека, История,
Поиск и Мини-плеер перерисовывались по 2 раза в секунду, хотя позиция им не
нужна. Дополнительно:

- `refreshWarp()` читал JSON-индекс WARP и перебирал сетевые интерфейсы прямо
  на главном потоке;
- экран поиска на каждую строку вызывал `isTrackDownloaded()` — скан библиотеки
  O(n) на строку;
- `LibraryScreen` строил обложки-коллажи, вызывая `vm.playlistTracks()` на
  каждый плейлист: O(плейлисты × треки) на главном потоке;
- у списков не было стабильных `key`, у `items` — `contentType`;
- в ка��дом элементе/карточке заново создавались `Brush.linearGradient`.

## 2. Что сделано

| Файл | Изменение |
|---|---|
| `MainViewModel` | `playerChrome` (состояние без позиции, `distinctUntilChanged`) и `playerProgress` (грубый прогресс) |
| `MainScreen`, `MiniPlayer` | `playerChrome`; прогресс собирается внутри мини-плеера, а не на весь экран; градиент в `remember` |
| `HomeScreen` | `playerChrome`; мемоизация срезов; `refreshWarp()` — в `Dispatchers.IO` |
| `LibraryScreen` | `playerChrome`; запомненные срезы; один `associateBy` для коллажей вместо пересборки карты на каждый плейлист; градиенты в `remember` |
| `SearchScreen` | один набор «скачано» на результаты вместо O(n) на строку |
| `QueueScreen` | ключи `${track.id}#<вхождение>` — корректный reuse строк при повторах |
| `TrackRow`, `LibraryCards`, `Visuals` | градиенты/фильтры в `remember` |
| `ArtistScreen`, `DetailsScreen`, `RemoteAlbumScreen` | `playerChrome` вместо полного состояния |

`PlayerScreen` намеренно продолжает читать полный `vm.player` — там позиция
нужна для seekbar и текста.

## 3. Замеры

`adb shell dumpsys gfxinfo app.sonora` после одного и того же сценария
(старт → прокрутка Главной → Медиатека → прокрутка/переключение):

| Метрика | 2.0.0 | 2.1.0 |
|---|---|---|
| Janky frames | **52,3 %** | **32,4 %** |
| 50-й перцентиль кадра | 48 мс | **38 мс** |
| 90-й перцентиль | 101 мс | **61 мс** |
| 99-й перцентиль | 600 мс | **300 мс** |
| Slow UI thread | 95 кадров | — |

Цифры с эмулятора (софтверный GPU, debug-сборка), поэтому важна разница, а не
абсолютные миллисекунды. На устройстве будет заметно лучше.
