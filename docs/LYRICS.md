# Синхронизированный текст в плеере (Lyrics)

Состояние на **26.10.2026**. Караоке-лист: откуда берётся текст, как разбирается LRC и как ведёт
себя UI. Обогащение — в [DISCOVERY.md](DISCOVERY.md), правовая рамка — в [LEGAL.md](LEGAL.md).

## Откуда берётся текст

| Поле `Track` | Что это | Источник |
|---|---|---|
| `lyrics` | обычный текст | `plainLyrics` LRCLIB; если её нет — LRC без таймкодов |
| `syncedLyrics` | сырой LRC с таймкодами | `syncedLyrics` LRCLIB |

- `MetadataService` ищет текст на [LRCLIB](https://lrclib.net) (`GET /api/search`, ключ не нужен):
  сначала с исполнителем, затем только по названию; допуск по длительности ±15 с или ±20 %.
- `LibraryRepository.updateTrackMetadata` заполняет **только пустые** поля — сохранённый текст не затирается.
- Оба поля лежат в библиотеке, поэтому после одного обогащения караоке работает офлайн.
- Кнопка «Текст» в плеере видна, если непусто хотя бы одно из полей.

## Формат LRC

| Форма | Пример | Результат |
|---|---|---|
| Минуты:секунды | `[00:42] слова` | 42 000 мс |
| С дробной частью | `[00:42.35] слова` | 42 350 мс |
| Дробная часть через `:` | `[00:42:35] слова` | 42 350 мс |
| Несколько таймкодов | `[00:42][01:15.5] припев` | две записи с одним текстом |
| Таймкод без текста | `[02:03.00]` | строка `♪` (инструментальная пауза) |
| Служебные теги | `[ar:]`, `[ti:]`, `[al:]`, `[by:]`, `[offset:]`, `[re:]`, `[ve:]`, `[length:]`, `[tool:]` | игнорируются |

Дробная часть нормализуется: `5` → 500 мс, `35` → 350 мс, `345` → 345 мс. Записи сортируются
по времени; строки без таймкодов отбрасываются. Если таймкодов нет вовсе, `parseLrc` возвращает
`null` — лист переходит в запасной режим.

## Поведение листа

- **Bottom sheet** (`ModalBottomSheet`, `skipPartiallyExpanded = true`); заголовок — название трека,
  подпись «Синхронизированный текст» (в запасном режиме — «Текст песни»).
- **Активная строка** — последняя, чей таймкод уже наступил (`timeMs <= positionMs`): `primary` +
  `FontWeight.SemiBold`; соседние строки — `onSurfaceVariant` с затуханием по расстоянию (0.62 → 0.22).
  До первой строки активной нет — все строки одинаково приглушены.
- **Авто-прокрутка**: `animateScrollToItem(index, scrollOffset = -viewportHeight/3)` ставит активную
  строку примерно на треть высоты списка от верха.
- **Пауза авто-прокрутки**: ручной скролл ловится по `DragInteraction.Start` в `listState.interactionSource`
  (своя анимация такого события не даёт), а возврат — через 3 секунды после конца скролла
  (`snapshotFlow { listState.isScrollInProgress }`).
- **Тап по строке** → `onSeek(line.timeMs)` → `MainViewModel.seekTo` → `PlaybackController.seekTo`;
  позиция обновляется, подсветка и прокрутка переезжают на выбранное место.
- **Запасной режим**: обычный текст (`lyrics`, иначе LRC без таймкодов) в `Column` + `verticalScroll`,
  без подсветки и без перемотки.

## Ограничения

- Подсветка **построчная**, не пословная: «бегущей строки» нет.
- `[offset:]` **не применяется** — тег игнорируется; рассинхрон исправляется только в самой базе LRCLIB.
- Встроенные в файлы тексты (`ID3 SYLT`/`USLT`) и локальные `.lrc` рядом с треком не читаются — только LRCLIB.
- Нет перевода, транслитерации и романизации.
- `positionMs` обновляется раз в ~500 мс: смена строки запаздывает до половины секунды; на паузе позиция замирает.
- Возможен чужой текст под верным названием (общественная база частично отсекается фильтром по длительности).
- Разобранный LRC не кэшируется между открытиями: парсинг дешёвый и выполняется при открытии листа.
