# Стриминг YouTube в РФ без VPN и WARP

> Статус: **1.6.0**. Документ объясняет, что именно блокируется, почему старый
> yt-dlp не спасал и как Sonora теперь пытается играть музыку без включённого
> WARP/VPN. Настройки — «Настройки → Поток и сеть».

## 1. Что блокируется

YouTube состоит из двух разных частей:

| Часть | Домен | Работает в РФ |
|---|---|---|
| Метаданные, поиск, плейлисты | `music.youtube.com`, `youtubei.googleapis.com` | Обычно да |
| Медиа (звук и видео) | `*.googlevideo.com` | Чаще всего нет: 403/обрыв/замедление до нуля |

Поэтому картина «трек находится, обложка есть, а при нажатии Play — ошибка»
нормальна: блокируется именно медиа-запрос. **Ни один флаг yt-dlp не обходит
сетевую блокировку**: если IP не пускают на `googlevideo`, клиент получит 403
(InnerTube, yt-dlp, ffmpeg, любой другой). Это ограничение провайдера/YouTube,
а не баг приложения.

Что реально можно сделать без VPN/WARP:

1. **Убедиться, что проблема не в устаревшем yt-dlp.** YouTube ломает старые
   сборки за недели — им требуется актуальный экстрактор и JavaScript-рантайм.
2. **Проверить, не блокируется ли только IPv4** — на части провайдеров IPv6
   не попадает под ограничение.
3. **Использовать медиашлюз** (публичные зеркала Invidious/Piped), который
   скачивает медиа своим «выходом» и отдаёт приложению готовый аудиопоток.

## 2. Что изменилось в 1.6.0

### 2.1. yt-dlp обновляется сам

Библиотека `youtubedl-android 0.18.1` везёт сборку **yt-dlp 2025.11.12** — она
устаревает за недели. Встроенный `updateYoutubeDL()` ходит в `api.github.com`,
а тот отдаёт 60 запросов в час на IP и часто отвечает 403 (общий IP оператора,
VPN-выход, WARP). Поэтому Sonora:

- скачивает zipapp **напрямую**:
  `https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp`;
- проверяет, что это настоящий zipapp, читает версию из `yt_dlp/version.py`;
- ставит его в `noBackupFilesDir/youtubedl-android/yt-dlp/yt-dlp`;
- делает smoke-тест `--version` и **откатывает** файл при ошибке;
- встроенный `api.github.com`-апдейтер остаётся резервом;
- автоматически не чаще раза в сутки, вручную — кнопкой «Обновить yt-dlp сейчас».

Проверено на устройстве: `2025.11.12 → 2026.10.26`, поток после обновления
резолвится и проходит Range-проверку.

Библиотека сама добавляет к каждому вызову
`--js-runtimes quickjs:<nativeLibraryDir>/libqjs.so` — QuickJS-рантайм для
JavaScript-челленджей YouTube уже в APK.

### 2.2. Перебор клиентов и протоколов

`YtDlpResolver` пробует несколько наборов `--extractor-args` и IP-протоколов,
пока какой-то не даст **играющую** ссылку:

```
youtube:player_client=default,tv_simply
youtube:player_client=tv,android_vr
youtube:player_client=web_safari,web_embedded
youtube:player_client=ios,mweb
youtube:player_client=android,web
```

- последний удачный набор запоминается и пробуется первым (быстрее повторный старт);
- режим сети YouTube: «Авто» (оба протокола) / IPv4 / IPv6;
- каждый результат проверяется реальным `Range: bytes=0-2047` запросом.

### 2.3. Проверка ссылки перед воспроизведением

Direct-ссылки YouTube подписаны под IP, клиента и PoToken. Резолв может пройти,
а загрузка — упасть с 403. Поэтому Sonora по умолчанию проверяет ссылку
маленьким Range-запросом и отдаёт в плеер только ту, что реально отвечает
`200/206` и аудио-байтами. Настройка — «Проверять ссылку перед воспроизведением».

### 2.4. Медиашлюз без VPN

Если прямой путь (InnerTubeX → InnerTube → yt-dlp) не даёт играющую ссылку,
включается `RelayGateway` — публичные зеркала:

- **Invidious**: `/api/v1/videos/<id>?local=true` → зеркало отдаёт
  проксированные аудио-ссылки (itag 139/140/251 и др.);
- **Piped**: `/streams/<id>` → `audioStreams[]`;
- зеркала проверяются health-check'ом, порядок: последнее рабочее →
  встроенный список → автопоиск;
- автопоиск — `https://api.invidious.io/instances.json`;
- свой список — «Серверы шлюза» (по одному адресу в строке);
- ссылки кэшируются на 5 минут, каждая проверяется Range-запросом и
  контент-типом (защита от «206 + HTML-ошибка»).

Источник потока «Шлюз» заставляет использовать только зеркала — удобно, когда
прямой YouTube заблокирован полностью.

### 2.5. Честная диагностика

«Проверить поток» теперь показывает покомпонентно:

```
Видео: dQw4w9WgXcQ
Прямой YouTube → InnerTubeX: OK · 136 кбит/с · 723 мс
yt-dlp 2026.10.26 → OK (audio/webm)
Медиашлюз → ни одно зеркало не ответило
Прямой доступ работает: VPN и WARP не нужны.
```

## 3. Что делать, если не играет

1. Настройки → Поток и сеть → **«Обновить yt-dlp сейчас»** (частая причина 403).
2. **«Проверить поток»** — посмотреть, какой шаг падает.
3. **«Проверить шлюзы»** — какие зеркала живы сейчас.
4. Попробовать «Сеть YouTube → IPv6» (или IPv4), если провайдер фильтрует один
   из протоколов.
5. Добавить своё зеркало в «Серверы шлюза» (любой Invidious с включённым
   `local`-прокси) — публичные инстансы живут недолго.
6. Если ничего не помогло — включить WARP на Главной или указать прокси для
   yt-dlp. Это последний рубеж, а не требование для всех.

## 4. Честные ограничения

- **Полная блокировка медиа по IP не обходится клиентом.** Если `googlevideo`
  недоступен, а зеркала тоже заблокированы провайдером, без WARP/прокси/VPN
  звука не будет — это физика сети, а не недоработка приложения.
- **Публичные зеркала нестабильны.** Инстансы умирают, отключают API,
  упираются в бот-защиту YouTube. Приложение перебирает их, кэширует рабочие и
  позволяет добавить свои. Из РФ часть зеркал может быть недоступна.
- **Зеркало видит, что вы слушаете.** Это чужой сервер; для приватности
  предпочтительнее прямой путь или свой сервер.
- **Условия YouTube.** Использование неофициальных клиентов и прокси нарушает
  ToS YouTube; ответственность за использование — на пользователе. Sonora не
  обходит DRM и не распространяет контент. Подробнее — `LEGAL.md`,
  `PLATFORM-FACTS.md`.

## 5. Замеры 29.10.2026: почему «просто зеркало» не панацея

Проверяли 20+ публичных зеркал и отдельно — доступность из российских сетей
(Globalping: Timeweb, Selectel, Yandex.Cloud, Cloud.ru). Итог:

| Вариант | Результат |
|---|---|
| Invidious `/api/v1/videos?local=true` с аудио-байтами | 1 из 20 (`yt.chocolatemoo53.com`), из РФ — timeout |
| Invidious API вообще (все 6 из официального списка) | 403 «Endpoint disabled» / Cloudflare 403 / 404 / 451 |
| Piped `/streams/<id>` | JSON 200 из РФ, но `audioStreams` пуст (бот-защита YouTube) |
| Cobalt API | требует JWT (`error.api.auth.jwt.missing`) |
| Свои замеры в РФ | YouTube-медиа: 403; Cloudflare-зеркала «стоят» (~16 КБ/соединение) |

Выводы:

- **Публичные зеркала — best-effort.** Приложение перебирает их, кэширует
  рабочие, позволяет добавить свои, но гарантировать звук «из коробки» нельзя.
- **Единственный надёжный путь без VPN/WARP — свой релей**: Invidious/Piped на
  собственном VPS (или любой HTTP-прокси к `googlevideo`), добавленный в
  «Серверы шлюза». Такой сервер имеет «чистый» IP, и Sonora будет ходить через
  него как через обычный источник.
- **Легальные альтернативы YouTube в РФ**: Яндекс Музыка, VK Музыка, Zvuk.
  Sonora их пока не подключает, но это правильный путь для легального
  стриминга без обходов.
- **yt-dlp-обновление действительно нужно** (встроенная сборка 2025.11.12), но
  оно лечит устаревший экстрактор, а не сетевую блокировку IP.
