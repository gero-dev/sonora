# Метаданные, авторы и обложки

Sonora подтягивает данные о треках из нескольких независимых каталогов. Цель —
заполнить **альбом, год, обложку, автора, фото автора, биографию и текст**, не
затирая то, что уже есть в тегах файла.

Документ описывает источники, приоритеты, кэш и правила нормализации авторов.

---

## 1. Источники

| Источник | Что даёт | Ключ | Примечание |
|---|---|---|---|
| **MusicBrainz** | канонический artist-credit, альбом, год, MBID записи | не нужен, обязателен User-Agent | 1 запрос/сек, выбирается студийный альбом, а не сборник |
| **Cover Art Archive** | обложка релиза 500 px | не нужен | работает по release id из MusicBrainz, может отдать 404 |
| **iTunes Search API** | обложка 1000×1000, альбом, год, имя автора | не нужен | `entity=song`, до 10 кандидатов |
| **Deezer API** | обложка 1000×1000, альбом, год, имя и фото автора | не нужен | фото — `picture_xl` |
| **TheAudioDB** | обложка альбома, фото автора, биография, жанр | публичный тестовый ключ `2` | может быть недоступен/403; после 403 отключается до перезапуска |
| **Wikipedia** | фото и краткая биография автора | не нужен | английская и русская; результат проверяется на музыкальные признаки |
| **InnerTube (YouTube Music)** | обложка, альбом, имя автора | не нужен | fallback-поиск, если каталоги не дали обложку/автора |
| **LRCLIB** | обычный и синхронизированный текст | не нужен | отдельно от «метаданных», но в том же кэше |

Все провайдеры, кроме MusicBrainz, опрашиваются параллельно. Для каждого
действует таймаут 12 секунд (Wikipedia — 15), чтобы один медленный сервис не
задерживал обогащение.

---

## 2. Что и откуда берётся

### 2.1. Обложка

Приоритет:

1. **Deezer** — `cover_xl`, обычно 1000×1000.
2. **TheAudioDB** — `strAlbumThumb` / `strTrackThumb`.
3. **iTunes** — `artworkUrl100`, увеличенный до `1000x1000`.
4. **Cover Art Archive** — `front-500` по выбранному релизу.
5. **InnerTube** — превью YouTube Music, увеличенное до 1000 px.

Текущая обложка заменяется только если она пустая или является маленьким
превью YouTube (`=w120-h120`, `=s120`, меньше 600 px). Встроенная обложка
локального файла не затирается.

Для скачанных треков обложка кладётся в `filesDir/covers`, поэтому видна
офлайн. Для онлайн-треков используется URL и кэш Coil.

### 2.2. Автор

Приоритет имени:

1. **MusicBrainz artist-credit** — каноническое имя, включая нескольких авторов.
2. **TheAudioDB** `strArtist`.
3. **Deezer** `artist.name`.
4. **iTunes** `artistName`.
5. **InnerTube** — имя исполнителя из поиска.
6. Очищенное текущее значение.

Имя применяется, если текущее пустое, является заглушкой («Unknown Artist»,
«YouTube Music») или похоже на канал («Nirvana - Topic», «NirvanaVEVO»,
«Nirvana Official»). Настоящие имена вроде «Earth, Wind & Fire» и
«Tyler, The Creator» не режутся.

### 2.3. Фото и биография автора

| Поле | Приоритет |
|---|---|
| Фото | TheAudioDB → Deezer `picture_xl` → Wikipedia (originalimage/thumbnail) |
| Биография | TheAudioDB `strBiographyEN` → Wikipedia `extract` |
| Жанр | TheAudioDB `strGenre` |

Фото автора хранится в `Track.extra["artistImageUrl"]`. Для скачанных треков
дополнительно кэшируется файл и путь `artistImageUri`.

В Медиатеке вкладка **Исполнители** показывает фото автора (если найдено), а не
обложку альбома. На экране исполнителя под именем выводится биография и жанр.

### 2.4. Альбом и год

- Альбом: iTunes → Deezer → TheAudioDB → MusicBrainz → InnerTube.
- Год: iTunes → Deezer → TheAudioDB → MusicBrainz.
- MusicBrainz выбирает официальный полноформатный альбом; сборники, концертники
  и «Greatest Hits» штрафуются.
- Если текущий альбом — имя папки (`Music`, `Download`, `Unknown Album`), он
  считается пустым и заменяется.

### 2.5. Текст

- LRCLIB: сначала с исполнителем, затем только по названию.
- Синхронизированный LRC сохраняется отдельно и используется караоке-режимом.
- Для YouTube-треков дополнительно используется вкладка Lyrics InnerTube.

## 3. Алгоритм поиска

```
MetadataService.lookup(track)
  → normalizeTitle / normalizeArtist
  → кэш (artist|title) свежий? вернуть
  → параллельно:
      MusicBrainz recording search
      LRCLIB
      iTunes Search
      Deezer Search + Deezer artist
      TheAudioDB searchtrack + searchartist
  → если нет обложки/автора:
      InnerTube search (8 результатов)
  → если нет фото/биографии:
      Wikipedia EN → Wikipedia RU
  → merge()
  → MetadataCache.put()
```

Каждый кандидат проверяется по:

- названию — без регистра, скобок и служебных пометок;
- исполнителю — с учётом «The», диакритики и `feat.`;
- длительности — допуск 25 секунд (InnerTube — 10 секунд).

Неподходящие кандидаты отбрасываются, чтобы не приклеить обложку чужой песни
или биографию другого исполнителя.

## 4. Нормализация авторов

`ArtistNames` (`data/metadata/ArtistNames.kt`):

| Вход | Выход |
|---|---|
| `Nirvana - Topic` | `Nirvana` |
| `NirvanaVEVO` | `Nirvana` |
| `Nirvana - Official` | `Nirvana` |
| `Nirvana Official` | `Nirvana` |
| `Earth, Wind & Fire` | без изменений |
| `The Beatles` | без изменений, но группируется с `Beatles` |

Ключ группировки:

- нижний регистр;
- удаление диакритики (`Beyoncé` → `Beyonce`);
- удаление пунктуации;
- удаление ведущего `The`;
- схлопывание пробелов.

Это исправляет дубли исполнителей в Медиатеке и на экране альбома.

## 5. Кэш

Файл: `filesDir/metadata_cache.json`.

- Ключ: `исполнитель|название` в нижнем регистре.
- Успешные данные: **30 дней**.
- «Ничего не найдено»: **6 часов** — чтобы временный сбой провайдера не
  закэшировался на месяц.
- `schemaVersion = 2`: после обновления старые записи один раз перезапрашиваются,
  чтобы появились фото/биография/жанр.
- Очистка: **Настройки → Очистить кэш метаданных**.

Кэш общий для локальных и онлайн-треков. Повторное обогащение не делает сетевых
запросов, если запись свежая.

## 6. Настройки

**Настройки → Библиотека**:

- **Искать метаданные и тексты онлайн** — включает автопоиск после сканирования.
- **Обогатить метаданные сейчас** — вручную обработать треки, у которых нет
  альбома, обложки, автора, фото/биографии или текста.
- **Очистить кэш метаданных** — форсировать повторный поиск.

Кандидаты на обогащение включают треки без фото автора, поэтому после первого
запуска новой версии библиотека один раз пройдёт по трекам и подтянет портреты.

## 7. Если данных нет

| Симптом | Причина | Что делать |
|---|---|---|
| Нет обложки | все каталоги ответили 404/пусто | вручную вложить обложку в тег или повторить позже |
| Нет фото автора | Deezer/Wikipedia не нашли исполнителя | проверьте написание; для редких артистов фото может отсутствовать |
| Неверный автор | в тегах имя канала | нажмите «Обогатить метаданные», Sonora заменит `- Topic`/VEVO |
| Дубли исполнителей | старые записи с разными вариантами имени | обогатите метаданные; группировка уже игнорирует регистр и `The` |
| Биография на другом языке | English/Wikipedia RU не нашли | это нормально для локальных/редких артистов |
| TheAudioDB не отвечает | сервер блокирует тестовый ключ | провайдер отключается, остальные источники работают |
| Метаданные «зависли» | кэш хранит отрицательный результат | очистите кэш метаданных и повторите |

## 8. Приватность и правовая рамка

- Наружу уходят только поисковые запросы (название, исполнитель, длительность).
- Файлы и библиотека не загружаются ни на один сервер.
- Обложки и фото скачиваются по HTTPS и кэшируются локально.
- Источники — публичные API; ключи не используются, кроме тестового ключа
  TheAudioDB.
- Условия MusicBrainz требуют корректный User-Agent — он задан.
- Тексты песен и фото могут быть объектами авторского права; Sonora показывает
  их для личного некоммерческого использования.

См. [LEGAL.md](LEGAL.md) и [PLATFORM-FACTS.md](PLATFORM-FACTS.md).

## 9. Как добавить новый источник

1. Добавить функцию `lookupXxx(title, artist, durationMs): ProviderData?` в
   `MetadataService.kt`.
2. Проверять кандидатов через `sameTitle`, `sameArtist`, `durationMatches`.
3. Вернуть `ProviderData` с полями `coverUrl`, `album`, `year`, `artist`,
   `artistImageUrl`, `artistBio`, `genre`, `source`.
4. Добавить вызов в `lookup()` (параллельно, с `withTimeout`).
5. Добавить поля в `merge()` с явным приоритетом.
6. Добавить имя источника в `providers` и в документацию.
7. Если появились новые поля — расширить `TrackMetadata`, `CachedMetadata`,
   `MetadataCache.put()` и поднять `CACHE_SCHEMA_VERSION`.

Ключевые файлы:

- `data/metadata/MetadataService.kt` — провайдеры, слияние, нормализация;
- `data/metadata/MetadataCache.kt` — постоянный кэш и версия схемы;
- `data/metadata/ArtistNames.kt` — имена и группировка;
- `data/library/LibraryRepository.kt` — применение метаданных, альбомы/авторы;
- `core/model/Models.kt` — `TrackMetadata`;
- `ui/screens/DetailsScreen.kt` — фото/биография автора;
- `ui/screens/LibraryScreen.kt` — вкладка «Исполнители».
