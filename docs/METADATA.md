# Метаданные, авторы и обложки

Sonora подтягивает данные о треках из нескольких независимых каталогов. Цель —
заполнить **альбом, год, обложку, автора, фото автора, биографию и текст**, не
затирая то, что уже есть в тегах файла.

Документ описывает источники, приоритеты, кэш, правила нормализации авторов, а также
метаданные из файлов рядом с треками (sidecar) и локальные обложки.

---

## 1. Источники

| Источник | Что даёт | Ключ | Примечание |
|---|---|---|---|
| **MusicBrainz** | канонический artist-credit, альбом, год, MBID записи | не нужен, обязателен User-Agent | 1 запрос/сек, выбирается студийный альбом, а не сборник |
| **Cover Art Archive** | обложка релиза 500 px | не нужен | работает по release id из MusicBrainz, может отдать 404 |
| **iTunes Search API** | обложка 1000×1000, альбом, год, имя автора | не нужен | `entity=song`, до 10 кандидатов |
| **Deezer API** | обложка 1000×1000, альбом, год, имя и фото автора | не нужен | фото — `picture_xl` |
| **TheAudioDB** | обложка альбома, фото автора, биография, жанр | публичный тестовый ключ `2` | может быть недоступен/403; после 403 отключается до перезапуска |
| **Wikipedia** | фото и краткая биография автора | не нужен | английская и русская; результат проверяется на музыкальные признаки |
| **InnerTube (YouTube Music)** | обложка, альбом, имя автора | не нужен | fallback-поиск, если каталоги не дали обложку/автора |
| **LRCLIB** | обычный и синхронизированный текст | не нужен | отдельно от «метаданных», но в том же кэше |
| **Файлы рядом с треком (sidecar)** | название, исполнитель, альбом, год, обложка, текст | не нужен | JSON/NFO/LRC и `cover.*`, читаются локально; см. раздел 3 |

Все провайдеры, кроме MusicBrainz, опрашиваются параллельно. Для каждого
действует таймаут 12 секунд (Wikipedia — 15), чтобы один медленный сервис не
задерживал обогащение.

## 2. Что и откуда берётся

### 2.1. Обложки

Для локального файла обложка ищется в таком порядке:

1. **Встроенная обложка из аудиофайла** — ID3 `APIC` (MP3), picture-блок FLAC, `covr` в MP4/M4A.
   `LocalArtwork.embedded()` достаёт картинку через `MediaMetadataRetriever.getEmbeddedPicture`,
   кладёт её в `filesDir/covers/<sha1(trackId)>.jpg` (PNG сохраняется как `.png`) и возвращает
   file-URI. Уже извлечённый файл повторно не создаётся.
2. **Файл в папке с музыкой** — `cover.jpg`, `folder.jpg`, `albumart.jpg` или `front.jpg`
   (без учёта регистра), `LocalArtwork.folderCover()`.
3. **Онлайн-каталоги** — Deezer и TheAudioDB, затем iTunes (несколько вариантов запроса:
   `artist title`, `title artist`, `album …`; если песня не нашлась — отдельный album-fallback),
   затем Cover Art Archive по релизу/альбому, затем InnerTube.

Обложка из п. 1–2 работает **без сети** и считается приоритетной: онлайн-поиск заменяет
текущую обложку, только если она пустая или является маленьким превью YouTube
(`=w120-h120`, `=s120`, меньше 600 px). Встроенная картинка файла и `cover.jpg` онлайн-поиском
не затираются.

**Что улучшилось.** У локальных треков обложка появляется сразу после сканирования, офлайн и
без обращения к каталогам. Онлайн-подбор стал точнее: iTunes и Deezer перебирают варианты
запроса, учитывают подсказки альбома и года из тегов и sidecar-файлов, а кандидат с обложкой
получает больший score. Cover Art Archive и старый album-fallback в iTunes остаются как
дополнительные источники.

**Как проверить.** Настройки → Библиотека → включите «Читать метаданные из файлов рядом
с треками» и «Брать обложки из аудиофайлов», затем нажмите «Найти пропущенные обложки»:
кнопка обрабатывает локальные треки без обложки (до 40 за запуск, последовательно, чтобы
не злить API), показывает прогресс «Ищу… X из Y» и итог «Готово: найдено обложек — N».
Если обложки уже есть у всех, приложение сообщит «У всех локальных треков уже есть обложки».
Для проверки офлайна включите авиарежим: обложки из тегов и папок должны остаться на месте.

Для скачанных треков обложка кладётся в `filesDir/covers`, поэтому видна
офлайн. Для онлайн-треков используется URL и кэш Coil.

### 2.2. Автор

Приоритет имени:

1. **MusicBrainz artist-credit** — каноническое имя, включая нескольких авторов.
2. **TheAudioDB** `strArtist`.
3. **Deezer** `artist.name`.
4. **iTunes** `artistName`.
5. **InnerTube** — имя исполнителя из поиска.
6. Очищенное текущее значение.

Имя применяется, если текущее пустое, является заглушкой («Unknown Artist»,
«YouTube Music») или похоже на канал («Nirvana - Topic», «NirvanaVEVO»,
«Nirvana Official»). Настоящие имена вроде «Earth, Wind & Fire» и
«Tyler, The Creator» не режутся.

### 2.3. Фото и биография автора

| Поле | Приоритет |
|---|---|
| Фото | TheAudioDB → Deezer `picture_xl` → Wikipedia (originalimage/thumbnail) |
| Биография | TheAudioDB `strBiographyEN` → Wikipedia `extract` |
| Жанр | TheAudioDB `strGenre` |

Фото автора хранится в `Track.extra["artistImageUrl"]`. Для скачанных треков
дополнительно кэшируется файл и путь `artistImageUri`.

В Медиатеке вкладка **Исполнители** показывает фото автора (если найдено), а не
обложку альбома. На экране исполнителя под именем выводится биография и жанр.

### 2.4. Альбом и год

- Альбом: iTunes → Deezer → TheAudioDB → MusicBrainz → InnerTube.
- Год: iTunes → Deezer → TheAudioDB → MusicBrainz.
- MusicBrainz выбирает официальный полноформатный альбом; сборники, концертники
  и «Greatest Hits» штрафуются.
- Если текущий альбом — имя папки (`Music`, `Download`, `Unknown Album`), он
  считается пустым и заменяется.

### 2.5. Текст

- LRCLIB: сначала с исполнителем, затем только по названию.
- Синхронизированный LRC сохраняется отдельно и используется караоке-режимом.
- Для YouTube-треков дополнительно используется вкладка Lyrics InnerTube.

## 3. Метаданные из файлов (sidecar)

Рядом с аудиофайлом можно положить файл с метаданными — Sonora прочитает его при сканировании
и использует как источник данных. Это работает офлайн и не требует сети; включено по умолчанию
переключателем «Читать метаданные из файлов рядом с треками».

### 3.1. Какие файлы читаются

| Файл рядом с треком | Что даёт |
|---|---|
| `<имя>.json` | объект или массив: `title`, `artist`, `album`, `year`, `cover`/`coverUrl`/`artwork`, `lyrics`, `syncedLyrics` |
| `<имя>.nfo` | XML-разметка: `<album>`, `<year>`, `<artist>`, `<title>`, `<thumb>`, `<lyrics>` |
| `<имя>.lrc` | синхронизированный текст: `[mm:ss.xx]` → `syncedLyrics`, он же без таймкодов → `lyrics` |
| `album.json` | общие данные папки: альбом, год, обложка |
| `cover.jpg` / `folder.jpg` / `albumart.jpg` / `front.jpg` | обложка папки (см. «Обложки») |

Если это плоский `.json` с массивом треков, запись выбирается по «Исполнитель - Название» из
имени файла (при отсутствии совпадения — первая). Непустые поля sidecar перекрывают пустые и
заглушки в треке («Unknown Artist», имя папки вместо альбома); год и ссылка на обложку
сохраняются в `extra`. В JSON также понимается `synced_lyrics` как синоним `syncedLyrics`.

### 3.2. Где применяется

- **Локальные файлы** — рядом с каждым треком.
- **Треки из MediaStore** — best-effort: путь собирается из `RELATIVE_PATH` и `DISPLAY_NAME`;
  если файл не найден, трек просто обрабатывается без sidecar.
- **Папки** — при сканировании папки `album.json` и `cover.jpg` относятся ко всем трекам.

Подсказки альбома и года из sidecar используются и в онлайн-поиске: с ними iTunes/Deezer
находят правильный релиз и обложку чаще, чем по одному «исполнитель + название».

### 3.3. Импорт метаданных из файла

Кнопка **«Импортировать метаданные из файла»** (Настройки → Библиотека) принимает JSON, CSV
и NFO через системный выбор файлов. Строки сопоставляются с локальными треками по
нормализованным «исполнитель + название»; если исполнителя нет — по названию (точное, затем
частичное совпадение). Найденные треки обновляются: альбом, год, обложка, текст. CSV читается
по заголовкам `artist,title,album,year,cover,lyrics`; в NFO понимаются теги `<title>`,
`<artist>`, `<album>`, `<year>`, `<thumb>`, `<lyrics>`. Во время импорта показывается
состояние: сколько файлов, совпадений, обновлений и ошибок.

Импорт читает файлы **локально** — на сервер ничего не загружается.

## 4. Алгоритм поиска

```
MetadataService.lookup(track)
  → normalizeTitle / normalizeArtist
  → подсказки: album и year из тегов/sidecar
  → кэш (artist|title) свежий? вернуть
  → варианты запросов: «artist title», «title artist», «album …»
  → параллельно:
      MusicBrainz recording search
      LRCLIB
      iTunes Search (обложка 1000×1000)
      Deezer Search + Deezer artist
      TheAudioDB searchtrack + searchartist
  → если нет обложки/автора:
      Cover Art Archive по альбому → InnerTube search (8 результатов)
  → если нет фото/биографии:
      Wikipedia EN → Wikipedia RU
  → merge()
  → MetadataCache.put()
```

Каждый кандидат проверяется по:

- названию — без регистра, скобок и служебных пометок;
- исполнителю — с учётом «The», диакритики и `feat.`;
- длительности — допуск 25 секунд (InnerTube — 10 секунд);
- наличию обложки — кандидат с обложкой приоритетнее при прочих равных.

Если строгие фильтры не дают результата, поиск ослабляется (title + длительность или
title + альбом) и выбирается лучший кандидат по score. Неподходящие кандидаты отбрасываются,
чтобы не приклеить обложку чужой песни или биографию другого исполнителя.

## 5. Нормализация авторов

`ArtistNames` (`data/metadata/ArtistNames.kt`):

| Вход | Выход |
|---|---|
| `Nirvana - Topic` | `Nirvana` |
| `NirvanaVEVO` | `Nirvana` |
| `Nirvana - Official` | `Nirvana` |
| `Nirvana Official` | `Nirvana` |
| `Earth, Wind & Fire` | без изменений |
| `The Beatles` | без изменений, но группируется с `Beatles` |

Ключ группировки:

- нижний регистр;
- удаление диакритики (`Beyoncé` → `Beyonce`);
- удаление пунктуации;
- удаление ведущего `The`;
- схлопывание пробелов.

Это исправляет дубли исполнителей в Медиатеке и на экране альбома.

## 6. Кэш

Файл: `filesDir/metadata_cache.json`.

- Ключ: `исполнитель|название` в нижнем регистре.
- Успешные данные: **30 дней**.
- «Ничего не найдено»: **6 часов** — чтобы временный сбой провайдера не
  закэшировался на месяц.
- `schemaVersion = 2`: после обновления старые записи один раз перезапрашиваются,
  чтобы появились фото/биография/жанр.
- Очистка: **Настройки → Очистить кэш метаданных**.

Кэш общий для локальных и онлайн-треков. Повторное обогащение не делает сетевых
запросов, если запись свежая.

## 7. Настройки

**Настройки → Библиотека**:

- **Искать метаданные и тексты онлайн** — включает автопоиск после сканирования.
- **Читать метаданные из файлов рядом с треками** (вкл. по умолчанию) — JSON/NFO/LRC и
  `cover.jpg` в папке с музыкой.
- **Брать обложки из аудиофайлов** (вкл. по умолчанию) — встроенные ID3/FLAC/MP4-обложки,
  офлайн и точнее.
- **Импортировать метаданные из файла** — JSON/CSV/NFO: альбом, год, обложка, текст.
- **Найти пропущенные обложки** — до 40 локальных треков без обложки за запуск,
  последовательные запросы с прогрессом «Ищу… X из Y» и итогом «Готово: найдено обложек — N».
- **Обогатить метаданные сейчас** — вручную обработать треки, у которых нет
  альбома, обложки, автора, фото/биографии или текста.
- **Очистить кэш метаданных** — форсировать повторный поиск.

Кандидаты на обогащение включают треки без фото автора, поэтому после первого
запуска новой версии библиотека один раз пройдёт по трекам и подтянет портреты.

## 8. Если данных нет

| Симптом | Причина | Что делать |
|---|---|---|
| Нет обложки | нет встроенной картинки, `cover.jpg` рядом нет, каталоги ответили 404/пусто | вложить обложку в тег (ID3/FLAC/MP4), положить `cover.jpg` в папку или нажать «Найти пропущенные обложки» |
| Обложка из папки не подхватилась | файл называется иначе или лежит не рядом с аудио | поддерживаются `cover`/`folder`/`albumart`/`front` с расширениями `.jpg/.jpeg/.png/.webp`, без учёта регистра |
| Метаданные из `.json`/`.nfo` не применились | sidecar лежит не рядом с файлом или не совпал по названию | имя файла должно совпадать с аудио (`<имя>.json`), для плоского массива — совпасть title/artist |
| Нет текста песни | LRCLIB не нашёл, sidecar с текстом отсутствует | положить `<имя>.lrc` рядом с файлом и включить «Читать метаданные из файлов» |
| Нет фото автора | Deezer/Wikipedia не нашли исполнителя | проверьте написание; для редких артистов фото может отсутствовать |
| Неверный автор | в тегах имя канала | нажмите «Обогатить метаданные», Sonora заменит `- Topic`/VEVO |
| Дубли исполнителей | старые записи с разными вариантами имени | обогатите метаданные; группировка уже игнорирует регистр и `The` |
| Биография на другом языке | English/Wikipedia RU не нашли | это нормально для локальных/редких артистов |
| TheAudioDB не отвечает | сервер блокирует тестовый ключ | провайдер отключается, остальные источники работают |
| Метаданные «зависли» | кэш хранит отрицательный результат | очистите кэш метаданных и повторите |

## 9. Приватность и правовая рамка

- Наружу уходят только поисковые запросы (название, исполнитель, альбом, год, длительность).
- Файлы и библиотека не загружаются ни на один сервер; sidecar-файлы читаются локально.
- Обложки и фото скачиваются по HTTPS и кэшируются локально.
- Источники — публичные API; ключи не используются, кроме тестового ключа
  TheAudioDB.
- Условия MusicBrainz требуют корректный User-Agent — он задан.
- Тексты песен и фото могут быть объектами авторского права; Sonora показывает
  их для личного некоммерческого использования.

См. [LEGAL.md](LEGAL.md) и [PLATFORM-FACTS.md](PLATFORM-FACTS.md).

## 10. Как добавить новый источник

1. Добавить функцию `lookupXxx(title, artist, durationMs): ProviderData?` в
   `MetadataService.kt`.
2. Проверять кандидатов через `sameTitle`, `sameArtist`, `durationMatches`.
3. Вернуть `ProviderData` с полями `coverUrl`, `album`, `year`, `artist`,
   `artistImageUrl`, `artistBio`, `genre`, `source`.
4. Добавить вызов в `lookup()` (параллельно, с `withTimeout`).
5. Добавить поля в `merge()` с явным приоритетом.
6. Добавить имя источника в `providers` и в документацию.
7. Если появились новые поля — расширить `TrackMetadata`, `CachedMetadata`,
   `MetadataCache.put()` и поднять `CACHE_SCHEMA_VERSION`.

Ключевые файлы:

- `data/metadata/MetadataService.kt` — провайдеры, слияние, нормализация;
- `data/metadata/MetadataCache.kt` — постоянный кэш и версия схемы;
- `data/metadata/ArtistNames.kt` — имена и группировка;
- `data/library/LibraryRepository.kt` — применение метаданных, альбомы/авторы;
- `core/model/Models.kt` — `TrackMetadata`;
- `ui/screens/DetailsScreen.kt` — фото/биография автора;
- `ui/screens/LibraryScreen.kt` — вкладка «Исполнители».
