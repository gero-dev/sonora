# Безопасность

## Как сообщить

- **Не создавайте публичный Issue** для уязвимостей.
- Используйте приватный канал GitHub: **Security → Advisories → Report a vulnerability**
  (или напишите мейнтейнеру через профиль GitHub).
- Опишите: версию/коммит, шаги воспроизведения, влияние, возможный фикс; приложите PoC,
  если он безопасен.

Ответ — в течение 7 дней. После исправления уязвимость раскрывается в CHANGELOG.

## Что считается уязвимостью

- Утечка OAuth-токенов (Google/Spotify и т.п.) из `EncryptedSharedPreferences`.
- Обход проверки `state`/PKCE в OAuth-потоке.
- Возможность скачать/изменить файлы за пределами папки приложения через импорт (Takeout,
  SAF, DownloadManager).
- Path traversal в CSV/ZIP-импорте, zip-bomb, OOM на большом файле.
- Выполнение кода через WebView (JS-мосты отсутствуют — но проверить стоит).
- Утечка содержимого библиотеки или файлов наружу (приложение не отправляет их на сервер).

## Вне зоны ответственности

- Ограничения сторонних сервисов и их API (лимиты, блокировки, изменения политик).
- Проблемы устройства/прошивки/кастомных лаунчеров.
- Уязвимости сторонних библиотек — сообщайте апстриму, но дайте знать и сюда.

## Приватность

Sonora не имеет собственного бэкенда: библиотека, плейлисты и настройки хранятся локально,
токены — в зашифрованном хранилище устройства. Запросы идут напрямую к официальным API
(Google, MusicBrainz, LRCLIB, archive.org, Jamendo) и к сайту music.youtube.com в WebView.
