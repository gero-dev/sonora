## [2.3.0] - 2026-10-30

### NoHiT 0.3.0-alpha.2

- Вендоренный 
ohit-core обновлён с 0.1.1 до **0.3.0-alpha.2** (12 файлов):
  TLS-record фрагментация ClientHello (TLS_64/128/256, комбинации с TCP),
  SNI-aware разрез, HostPolicy (банки/госуслуги не трогаем), автосброс
  DNS-кэша при смене сети и фоновое обновление списка GeoHide.
- Автоподбор NoHiT теперь перебирает и новые TLS-стратегии; подпись стратегии
  в настройках показывает человекочитаемое имя.

### «Моя волна»: строгие фильтры и ReccoBeats

- Новый движок: WaveFilterEngine (жёсткие фильтры — источник, настроение,
  избранное, музыка-только, дизлайки, свежесть истории; пустой результат
  показывает причину и «Сбросить фильтры»), WaveMoodMatcher (профили
  настроений по фичам ReccoBeats + keyword-fallback), WaveFeatureIndex
  (кэш фич, вкусовой центроид), WaveRanker (45-дневный полураспад,
  штрафы за скипы, разнообразие артистов, новизна, similarity, seeded
  взвешенная выборка), WaveFeatureEnricher (фоновое обогащение фичами).
- ReccoBeats используется полностью: BPM/energy/valence/danceability/
  acousticness/instrumentalness влияют на настроение и ранжирование; запросы
  идут в фоне с таймаутом и пейсингом, оффлайн не мешают.
- Клик по треку в волне теперь играет всю волну с этого трека (раньше —
  одиночную очередь из локальной библиотеки, из-за чего не переключалось).

### Навигация и пульт

- Нижнее меню и мини-плеер больше не исчезают на «Обзоре» и «Подключениях»:
  всегда можно вернуться на Главную/в другие разделы; на «Обзоре» появилась
  кнопка назад; тап по вкладке всегда переключает раздел.
- Кнопка «назад» как в Spotify: первый тап на 3-й секунде перезапускает
  текущий трек, повторный — предыдущий (в приложении и в виджете).
- Автопереход: STATE_ENDED в плеере теперь сам запрашивает следующую пачку,
  короткая очередь проактивно расширяется, 
ext() синхронизирует очередь.

### Поиск песни по фрагменту

- На экране поиска — «Найти по фрагменту»: запись 8 с, распознавание через
  AudD (ключ опционален) или офлайн-отпечаток по своей фонотеке, затем
  фоновый поиск информации по названию/исполнителю (metadata + YouTube).
  Не прерывает воспроизведение, состояние переживает уход с экрана.
- Подробности и ограничения — docs/RECOGNITION.md.

### Прочее

- **Виджет запускает музыку без приложения на Android 14**: кнопки используют `PendingIntent.getForegroundService` (фоновый `startForegroundService` из broadcast теперь запрещён системой); ANR при старте сервиса устранён boot-уведомлением.
- **Перемешивание запоминается** после полной остановки приложения
  (shuffleEnabled в настройках применяется при подключении плеера).
- 125 unit-тестов, lint без ошибок.

## [2.0.0] - 2026-10-29

### NoHiT вместо WARP: DPI-обход без VPN

- Встроен **[NoHiT](https://github.com/Avedanger/NoHiT)** (Apache-2.0):
  DoH/GeoHide DNS, фрагментация TLS ClientHello, автоподбор стратегии
  (S1–S5) — исходники вендорены в pp/src/main/java/dev/nohit/core/.
- Поднят **локальный HTTP CONNECT-прокси** NohitProxy (только 127.0.0.1):
  через него идут OkHttp (Http.client), Ktor (InnerTubeX), ExoPlayer
  (OkHttpDataSource) и yt-dlp (--proxy). Первые байты каждого туннеля
  режутся по плану NoHiT, DNS резолвится через DoH/GeoHide.
- В «Настройки → Поток и сеть → DPI-обход (NoHiT)»: переключатель (по умолчанию
  включён), текущая стратегия и **«Автоподбор»** (AutoTuner, вручную и
  автоматически раз в неделю).
- WARP не удалён, а переведён в **резерв**: включается автоматически, если
  NoHiT не дал результата (на сетях с TSPU reassembly), чтобы стриминг
  продолжал работать.

### Результаты проверки на сети пользователя (без WARP)

- Прокси NoHiT запускается, AutoTuner находит рабочую стратегию
  (GeoHide DNS, split [2,2,2,2], 542 мс) для незаблокированных хостов;
- TLS до music.youtube.com через фрагментацию на этой сети всё равно
  обрывается (TSPU собирает TCP и читает SNI) — см. docs/NOHIT.md;
- поэтому WARP остаётся автоматическим резервом; при этом на сетях без
  reassembly NoHiT справляется сам и WARP не запускается.

## [1.7.0] - 2026-10-29

### Автопилот стриминга: сам находит рабочий способ

- **Проверка всех способов** (`data/streaming/StreamingAutoPilot`): прямой
  InnerTube, yt-dlp, медиашлюз и собственный WARP. Автопилот сам определяет,
  что работает на текущей сети, и выбирает порядок транспортов.
- **Быстрый признак DPI-блокировки**: если TLS до `music.youtube.com` рвётся
  (на реальной сети пользователя — RST по SNI), прямой путь и публичные зеркала
  заведомо мертвы (замеры: yt-dlp 0/13, зеркала 0/32) — автопилот сразу идёт в
  WARP, не тратя минуту на обречённые попытки.
- **Автопереключение при ошибке**: `PlaybackController` сообщает об ошибке
  источника, автопилот сбрасывает кэши ссылок, поднимает другой транспорт и
  переоткрывает текущий трек с той же позиции (до 2 попыток на трек).
- **Периодическая перепроверка**: при старте, при смене сети (NetworkCallback),
  при ошибке и раз в 10 минут (с кэшем результата на 30 минут).
- **Настройки**: «Поток и сеть → Автопилот» — автопилот, WARP-автопилот,
  авто-регистрация WARP, автопереключение потока, «Проверить все способы»
  (покомпонентный отчёт), «Перерегистрировать WARP», разрешение VPN.

### Собственный быстрый WARP-способ

- **Автоматическая регистрация свежего WARP-профиля** (`WarpAutoRegistrar`):
  Curve25519-ключ генерируется на устройстве, профиль через API Cloudflare
  импортируется как обычный `.conf`. Если API недоступен — используется
  встроенный профиль.
- **Запоминание рабочего конфига**: после первого handshake автопилот
  сохраняет `warpLastGoodConfigId` и выбирает его первым, а также предпочитает
  зеркальный endpoint вместо `engage.cloudflareclient.com:2408` (в РФ не
  отвечает). На замерах подключение сократилось с 24–28 с до **1–2 с**.
- **Проверка именно звука через WARP**: после handshake выполняется
  Range-запрос к медиа; если «голый» InnerTube упирается в бот-гейт, идёт
  yt-dlp с рабочими клиентами (`default,tv_simply` → `web_safari` → …).
- **Подтверждено на реальной сети РФ без VPN/WARP на ПК**: приложение само
  поднимает WARP-туннель (только для своего трафика) и воспроизводит трек —
  `PlaybackState.PLAYING`, звук через yt-dlp.

### Автоматизация проверки стриминга на ПК

- `scripts/dev/streaming-audit.py` — матрица проверок: DNS/TCP/TLS/HTTP по
  хостам YouTube (IPv4/IPv6), SNI-DPI-эксперимент, InnerTube (4 клиента),

- Результаты и разбор: `docs/PC-STREAMING-AUDIT.md`, JSON в `docs/ci/`.
- Вывод аудита: без WARP YouTube полностью блокируется DPI; с WARP yt-dlp
  отдаёт 10/13 вариантов со скоростью 643–2983 КиБ/с.

- **Диагностика «Проверить поток»**: покомпонентный отчёт (прямой InnerTube →
  yt-dlp → медиашлюз) с реальными кодами и подсказками; «Проверить шлюзы»

- Новый документ [docs/STREAMING-RF.md](docs/STREAMING-RF.md): что именно
  блокируется, почему флаги не обходят блокировку IP, замеры зеркал из РФ и

- **yt-dlp не является средством обхода блокировок.** Если провайдер/YouTube

  скачивание/поток с российского IP отдаёт 403 даже при включённом WARP.
- Для работы нужен рабочий egress: WARP/прокси/VPN, либо источники, доступные
  в РФ (SoundCloud, Jamendo, Archive.org — уже в приложении).

  открытые каталоги) и **кнопка «Текст»**, которая открывает караоке-лист; если текста нет,
  приложение сначала ищет его онлайн.
- **Туннель WARP**: необязательный per-app WireGuard-туннель Cloudflare WARP. Импорт `.conf`
  через SAF, приватный ключ хранится зашифрованно; через туннель идёт **только трафик
  Sonora**, остальные приложения — напрямую. Полезно, когда музыкальный сервис блокируется
  провайдером. Документация — [docs/WARP.md](docs/WARP.md).

- **Настройки**: раздел «Руководство» и раздел «Туннель WARP».

### Исправлено

  `/128` — конфиги wgcf/WARP импортируются без ручной правки.
- Ошибка импорта WARP-конфига показывается в интерфейсе, а не теряется молча.

  обогащённые ранее треки были перепроверены без ручной очистки кэша.
